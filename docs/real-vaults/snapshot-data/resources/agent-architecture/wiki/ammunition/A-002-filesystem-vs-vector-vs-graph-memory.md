# 一句话结论
向量记忆（mem0）适合通用事实检索（快、低成本、生态成熟）；图谱记忆（graphiti）适合实体关系推理和时序追溯（可推理、可演化、但高成本高延迟）；文件系统记忆（letta）适合需要版本控制和可审计的关键记忆（可回滚、人类可读、但检索效率低）。三者的核心取舍是：检索效率 vs 推理能力 vs 可审计性，根据场景优先级选择。

# 对比表

| 维度    | 向量记忆（mem0）     | 图谱记忆（graphiti）            | 文件系统记忆（letta）         |
| ----- | -------------- | ------------------------- | --------------------- |
| 核心优势  | 检索快、成本低、生态成熟   | 可推理、可演化、语义去重              | 可回滚、可审计、人类可读          |
| 核心劣势  | 无法推理关系、hash 去重 | 高成本、高延迟、复杂                | 检索效率低、无去重             |
| 检索方式  | 向量相似度+BM25     | 混合搜索+图谱遍历+BFS             | 文件系统遍历（agent 主动）      |
| 写入成本  | 单次 LLM 调用      | 多次 LLM 调用（抽取+去重）          | 无独立 LLM（含在主循环）        |
| 去重机制  | MD5 hash 精确    | LLM 语义去重（识别同义）            | 无显式去重                 |
| 版本化   | 无（更新覆盖）        | 时序属性（valid_at/expired_at） | Git 完整版本化（可回滚）        |
| 推理能力  | 无（扁平事实）        | 强（实体-关系-时序推理）             | 无（依赖 agent 推理）        |
| 可审计性  | 弱（无变更历史）       | 中（边失效保留历史）                | 强（Git log/diff/blame） |
| 人类可读性 | 弱（嵌入向量不可读）     | 中（图谱结构可读）                 | 强（Markdown 文件直接可读）    |
| 典型场景  | 通用 agent 记忆层   | 知识管理/关系推理/时序追溯            | 关键记忆审计/版本控制/实验分支      |

# 取舍论述
**向量记忆的核心取舍**：用"扁平事实+嵌入向量"换取检索效率和低成本。向量相似度搜索能快速找到语义相关的记忆，单次 LLM 调用提取记忆降低了写入成本，28 向量库+21 LLM 的生态成熟度使其易于集成。但代价是：无法进行实体关系推理（如"A 和 B 的关系如何随时间变化"），MD5 hash 去重无法识别同义实体，记忆更新直接覆盖旧值（无版本历史）。**何时选向量记忆**：当记忆主要是事实型（如"用户喜欢咖啡"），需要快速检索，且成本敏感时。

**图谱记忆的核心取舍**：用"实体-关系-时序结构"换取推理能力和可演化性。知识图谱能表达实体间的复杂关系，时序属性（valid_at/expired_at）保留记忆演化历史，LLM 语义去重能识别同义实体，BFS 图谱遍历支持关系推理。但代价是：多次 LLM 调用（抽取实体+抽取关系+语义去重）导致高成本高延迟，图谱结构复杂（四层节点+多层边）增加了实现和维护难度，4 图数据库后端的运维成本高于向量数据库。**何时选图谱记忆**：当记忆需要结构化推理（如"组织架构变动对项目的影响"）、时序追溯（如"用户偏好如何演化"）或语义去重（识别"张三"和"小张"是同一人）时。

**文件系统记忆的核心取舍**：用"Markdown 文件+Git 版本控制"换取可审计性和人类可读性。MemFS 将记忆存储为人类可读的 Markdown 文件，Git 版本化（memory-git.ts 61KB）支持任意历史版本回滚，Git log/diff/blame 可审计每次记忆变更，Worktree 隔离支持并行记忆分支实验。但代价是：检索依赖 agent 主动遍历文件系统（效率低于向量搜索和图谱遍历），无显式去重机制（重复记忆由 agent 自行判断），记忆质量依赖 agent 的文件组织能力。**何时选文件系统记忆**：当记忆需要严格的审计和版本控制（如医疗/法律/金融领域的关键决策记忆），或需要人类直接阅读和编辑记忆（如团队共享的知识库），或需要并行实验不同记忆策略（Worktree 分支）时。

# 面试 follow-up

#flashcards

三种记忆范式可以在同一个 agent 中分层使用吗？::可以，典型分层架构：①热记忆（向量记忆，mem0）——最近交互的事实，快速检索，低成本；②冷记忆（图谱记忆，graphiti）——长期知识和关系，高成本推理，按需触发；③审计记忆（文件系统记忆，letta Git）——关键决策和变更，可审计可回滚。通过 agent 编排层统一管理记忆写入路由（热→向量，关系→图谱，关键→文件系统），避免记忆冗余和一致性问题。
<!--SR:!2026-10-06,1,210-->

如何判断一个场景需要图谱记忆而不是向量记忆？::三个判断标准：①是否需要回答"关系型问题"——如"A 和 B 是什么关系""这个决策受哪些因素影响"，向量记忆只能返回相关事实，无法推理关系；②是否需要"时序追溯"——如"用户偏好如何随时间演化""组织架构变动历史"，图谱的时序属性（valid_at/expired_at）天然支持；③是否需要"语义去重"——如识别"张三"和"小张"是同一人，向量记忆的 MD5 hash 无法处理。满足任一标准即考虑图谱记忆。
<!--SR:!2026-10-09,4,270-->

文件系统记忆的检索效率低，如何优化？::四种优化策略：①建立索引——在 MemFS 之上维护一个轻量索引文件（如目录树+关键词映射），agent 先查索引再定位文件；②分层目录——按主题/时间/实体组织目录结构，减少遍历范围（letta 的 MEMORY_TREE_MAX_LINES/CHARS/CHILDREN_PER_DIR 限制防止目录过大）；③混合检索——将文件系统记忆的元数据（文件名/摘要/标签）同步到向量数据库，先向量检索定位文件，再读取文件内容；④agent 训练——通过 prompt 工程训练 agent 高效的文件系统遍历策略（如先 ls 再 cat，避免全量遍历）。
