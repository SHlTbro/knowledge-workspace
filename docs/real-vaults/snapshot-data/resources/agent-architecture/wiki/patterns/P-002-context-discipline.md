# 问题
长会话/长任务中上下文窗口膨胀：成本暴涨、注意力稀释、agent 跑偏。上下文是 agent 唯一的"工作内存"，是稀缺资源，必须主动管理而非被动堆积。

# 推荐用法
1. 设计任何 agent 时先回答：**这一步之后，上下文里应该剩什么？**（而不是"还需要加什么"）
2. 错误回填前先压缩：报错 → 一行原因 + 可行动建议，才进上下文。
3. 多任务不共用会话：一件任务一个窗口（对应因子 10）。
4. 状态放文件/数据库（本仓库的做法：知识即文件），上下文随时可以从状态重建（因子 12 的活例子）。

# 反面教训
- 把整个日志/整个文件灌进上下文"以防万一"。
- 用一个越来越长的会话连续干多件不相关的事。
- 让 agent 自己汇报"我觉得进展顺利"而不给环境反馈（S-001 的 ground truth 原则）。
