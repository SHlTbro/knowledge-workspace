## 机制
Agent 提议签名时，不只读 contract text/name/description（这些最容易被恶意方伪装），而是拉真实历史行为与链上活动。在 install / read / trust / submit / allowed 五个边界检查风险，低风险可继续，高风险要求真人物理确认。"not what the contract says, but what it has done"。

## 相对普通做法改变了什么
普通做法：Agent 读合约源码和描述 → 判断"看起来没问题" → 签名。恶意方最容易伪装的就是文本和 metadata。
本机制：真实观测行为 > 自我声明描述。五个边界分层检查，高后果动作要求物理确认。

## 适用场景
MCP tool runtime preflight、第三方 Skill 安全检查、合约/API 调用前验证、任何"不要信自我介绍，要看实际行为"的场景。
