## 机制
先提出多条候选 approach，不立即承诺其中一条；learned controller 决定哪些路径 expand、哪些 prune、哪些进入真实 test 验证。compiler error 和 failing test 反向影响 controller 对路径的权重。IDE 内展示整个搜索过程。

## 相对普通做法改变了什么
普通做法：single-shot 生成一条计划 → 沿这条路径改代码 → 遇到错误再修 → 如果最初 architecture assumption 错了，大量 token 用于修补同一个坏方向。
本机制：Branch-and-Verify Coding，失败证据会改变后续搜索，而不是 N 个答案最后投票。推理资源按证据动态分配。

## 适用场景
AI Coding 复杂任务、架构决策、多方案比较、任何"一条路走到底可能错"的场景。
