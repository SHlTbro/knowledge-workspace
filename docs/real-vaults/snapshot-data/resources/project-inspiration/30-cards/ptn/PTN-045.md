## 机制
Agent 的下一步动作目标是最大化信息增益，而不是立即修系统。观测现象 → 形成多个互斥根因假设 → 按信息增益/风险排序 probe → 只执行安全探针（read-only）→ 吸收结果 → 缩小根因集合。每轮只能选一个 probe，并声明它区分哪些假设。

## 关键设计
- hypothesis registry：3-5 个互斥假设
- safe probe catalog：metrics query、日志过滤、health check、dry-run、synthetic request
- 每轮一个 probe + 声明区分哪些假设 + 预期结果如何更新置信度
- side-effect ≠ NONE 的 probe 一律拒绝自动执行
- evidence ledger 直到根因置信度达标或升级人类

## 适用场景
SRE 故障诊断、企业问题定位、Bug 排查、任何"先确定问题在哪，再修"的场景。
