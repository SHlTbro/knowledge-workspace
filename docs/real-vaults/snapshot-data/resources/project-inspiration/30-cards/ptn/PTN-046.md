## 机制
代码 diff 不是"开发任务结束"，而是产生一组必须被重新验证的派生资产。文档、diagram、契约、示例都有 dependency edge。代码变更后自动找到可能受影响的 claim，只生成 stale candidates，不直接改事实。

## 关键设计
- Change Impact Map：commit → 受影响的 README/PRD/架构图/契约
- 三阶段分离：发现漂移 → 提出更新 → 验证事实
- 只生成 stale candidates，不自动写回
- 自动同步不能作为正确性证明

## 适用场景
AI Coding 后的文档同步、架构图维护、API 契约一致性、简历项目描述更新、任何"代码改了但文档没改"的场景。
