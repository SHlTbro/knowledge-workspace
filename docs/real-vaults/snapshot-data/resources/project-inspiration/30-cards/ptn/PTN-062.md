## 机制
用户描述 wish → 解析成签名的 on-chain schema → 如果当前 capability test 通过就执行，否则进入隔离资源 cell 保持 dormant。每次主要模型能力更新后重新运行 capability sweep；一旦公开 benchmark 首次满足预设条件，wish 被唤醒并执行。每个 capability run 有签名日志、pass/fail matrix 和可验证 attestation。

## 相对普通做法改变了什么
普通做法：失败后结束，或每天定时重试 → 不断烧模型、重复同一个不可能任务 → 没有客观标准判断"世界是否变了"。
本机制：Capability-triggered Retry，重试由"新证据"驱动而非"模型焦虑"驱动。适用于"当前模型做不到""某工具尚未支持""某 API 还没开放"的长期任务。

## 适用场景
长期 Agent 任务调度、等待模型能力提升、等待 API/工具支持、任何"现在做不到但未来可能"的场景。
