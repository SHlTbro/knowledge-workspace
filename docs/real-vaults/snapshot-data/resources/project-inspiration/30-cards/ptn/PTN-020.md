# 制度化反方与真实否决权 Institutionalized Dissent with Real Veto

## 一句话本质
给反方 Agent 明确任务、留痕和系统级否决权，而不是期待普通 reviewer 自发挑错或做表演式"讨论"。

## 结构
正方产出 → 专职 Dissent/Skeptic 基于确定性数据攻击 → veto 条件触发（如乐观≥50%但现实<25%）→ veto 改变最终决策状态 → 记录反方正确率。

## 改变了什么
传统"让另一个 LLM 审查"只是文本批评，不影响执行；这里反方有可执行的 veto 权，其输出是结构化的 veto_ids，直接进入最终裁决。

## 哪些只是包装
在 prompt 里写"请扮演反方"不是制度化；没有结构化 veto 条件和决策影响的都不算。

## 适用边界与误用
反方可能过度保守（veto 滥用），需跟踪其正确率并校准；veto 条件必须可审计，不能变成另一个黑箱。
