## 机制
不按"未测行数"排序，而是 AST 静态扫描构建调用图，找出存在 missing lines 且至少一个 caller 的函数，fully untested 优先，再按 caller count 排序。LLM 只能通过 read-only tool 阅读 top findings 的函数源码和 caller，输出 test priority + 理由。不执行被扫描代码。

## 相对普通做法改变了什么
普通做法：coverage report 列未测行数 → 从来没人调用的 helper 和被 37 个核心函数依赖的函数同样是"红色" → 工程师花时间测边缘代码。
本机制：测试优先级 = 未覆盖 × 被依赖程度 × 最近改动 × 失败历史。同样测试预算下捕获更多真实缺陷。

## 适用场景
AI Coding 测试治理、遗留代码测试优先级、CI/CD 测试资源分配、任何"覆盖率不是唯一指标"的场景。
