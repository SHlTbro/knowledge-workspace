## 机制
Decision-state Memory 而非 Transcript Memory。建立四类持久状态：DECISION（已决定什么）、EVIDENCE（依据是什么）、PENDING（还欠什么）、REJECTED_PATH（尝试过什么、为什么放弃）。新会话只加载当前有效状态与 source hash；旧的完整 transcript 留冷存储。跨机器、跨 Agent、跨 provider 同步同一个中间状态。

## 相对普通做法改变了什么
普通做法：把旧聊天全部塞给新 Agent → dead ends、过期 tool output、重复说明一起搬过去 → context 越"完整"越像搬家时舍不得扔垃圾。
本机制：只保存项目的未完成状态和决策证据，不保存每个 token。Memory 的 lifecycle 比容量更重要。

## 适用场景
跨会话 AI Coding、多 Agent 协作、长期项目上下文管理、任何"换环境不冷启动"的场景。
