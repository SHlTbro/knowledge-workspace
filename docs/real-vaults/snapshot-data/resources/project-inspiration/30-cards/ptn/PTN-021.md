# 副作用可逆性分类与补偿 Reversibility Taxonomy & Compensation

## 一句话本质
每个 tool call 执行前预先分类可逆性等级，失败时按逆序执行补偿，不可逆动作强制人工，不伪造"已撤销"。

## 结构
transaction 开始 → 每步记录 input/output/prior state → 分类 CLEAN/RESTORATIVE/TOMBSTONED/MITIGABLE/TERMINAL → 失败时逆序补偿可逆步 → TERMINAL 生成 human intervention → receipt。

## 改变了什么
传统"失败就 rollback"假设所有动作可逆；这里承认五种责任等级，每级有不同补偿合同，不可逆动作从设计上就不允许自动执行。

## 哪些只是包装
try/except 后调一个 undo() 不是分类；没有预先 reversibility_contract 和 prior state 快照的都不算。

## 适用边界与误用
外部 SaaS 的现实语义（邮件发出不能收回、文件恢复可能覆盖并发修改）是真正难点；补偿完备性需逐工具验证。
