## 机制
Web 用户和 AI Agent 共用同一后端 anti-Sybil rule。同一个人无论亲自操作还是让 Agent 操作，都映射到同一个 human key。数据库 UNIQUE(drop_id, human_key) 强制一个真实人只能一个名额。Agent 不是另一个身份域。

## 相对普通做法改变了什么
普通做法：proof-of-human 防 bot → 但真人验证一次后可以让 100 个 Agent 重复占名额。
本机制：配额绑定 human principal，不绑定 agent_id/session/API key。删掉 Agent3 再创建 Agent7 不能绕过限额。

## 适用场景
Personal Agent 配额管理、限量资源防女巫、招聘投递次数限制、免费试用额度、任何"一个人只能一个"的场景。
