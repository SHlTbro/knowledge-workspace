# 事件驱动动态组队 Event-Driven Dynamic Team Formation

## 一句话本质
业务事件发生后，按事件类型和失败信号动态招募必要 Agent 角色，而不是让固定全员团队常驻烧 token。

## 结构
事件检测 → 事件分类 → 按需发现/招募角色 → 并行窄任务 → 聚合 → 人/确定性 gate → 解散。

## 改变了什么
传统多 Agent 系统固定 Coder/Reviewer/Debugger 全员在线；这里角色是事件驱动的，简单任务只招 2 个，复杂事故才招 5-7 个。

## 哪些只是包装
固定团队里"有时不调用某个 Agent"不是动态组队；需要运行时角色发现和基于事件签名的选择逻辑。

## 适用边界与误用
角色发现机制本身需要维护；过度动态可能导致上下文碎片化；需记录每次组队决策供复盘。
