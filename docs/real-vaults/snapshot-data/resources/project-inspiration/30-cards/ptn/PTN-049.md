## 机制
Agent 的 trajectory 不应该一股脑存进训练集。先确定性过滤（parse error / tool error / 重复循环 / 空回答），再 LLM-as-judge 四轴评分（goal/efficiency/coherence/tool_use），然后多样性选择，最后对可挽救的低质量轨迹重新探索修复。产出的是 training-grade dataset，不是 raw log dump。

## 相对普通做法改变了什么
普通做法：sandbox 收集所有 rollout → 全量存训练集 → 失败轨迹和循环调用污染数据。
本机制：Generate → Evaluate → Filter → Select → Refine 五段流水线，确定性规则做廉价第一遍，LLM judge 做昂贵第二遍，失败但有学习价值的轨迹不丢弃而是修复。

## 适用场景
AI Coding 训练数据构建、Agent 经验沉淀、Skill 迭代数据源、RAG 问答质量过滤。
