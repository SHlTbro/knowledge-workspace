# 生成-裁决-反馈循环 Generate-Validate-Refine Loop

## 一句话本质
LLM 负责生成候选，确定性/领域规则裁决器负责否决，失败原因结构化喂回生成器重试，而不是再问一个 LLM"你觉得对不对"。

## 结构
Generator 产出候选 → Validator（确定性/MCP/本地编译）判定 → 成功则出口；失败则把 error report + failed candidate 回灌 Generator 进入 Correction Mode → 上限 N 次后转人工/降级。

## 改变了什么
传统是"LLM 生成 → LLM 自审 → 直接用"，自审无外部锚点；这里裁决器是独立权威系统（物理规则、编译器、schema），失败信号是机器可读的错误报告而非自然语言批评。

## 哪些只是包装
在 prompt 里加一句"请仔细检查"不是循环；没有独立裁决器和结构化错误回灌的都不算。

## 适用边界与误用
裁决器必须覆盖领域核心约束；覆盖不足时循环会在错误方向上反复；N 次上限和降级路径必须存在，否则死循环烧 token。
