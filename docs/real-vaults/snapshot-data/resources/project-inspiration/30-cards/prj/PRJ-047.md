## 项目证据
- 赛事：ETHGlobal New York 2026，World Track A (AgentKit) 第一名。
- 项目页：https://ethglobal.com/showcase/proof-of-human-1cg2d
- 技术：Next.js + TypeScript + PostgreSQL/Drizzle；World ID v4、Worldcoin AgentKit、World Chain Sepolia、CAIP-122/SIWE、EIP-191/ERC-1271；真实 USDC.e 测试网结算。

## 用户与痛点
限量商品、免费试用、预约名额等稀缺资源，本来可以用 proof-of-human 防 bot，但 Agent 时代又出现一层漏洞：真人先验证一次，然后让一堆 Agent 代表他重复占名额。

## 功能流
Web 用户通过 World ID 验证，或 AI Agent 每次请求携带 AgentKit 身份证明 → 后端解析出匿名 human identity → 数据库 UNIQUE(drop_id, human_key) 强制一个真实人只能一个 raffle slot → seedable random draw → winner 才执行 USDC 支付。

## 真正机制
【作者公开】Web 和 Agent 共用同一后端 anti-Sybil rule，Agent 不是另一个身份域；同一个人无论亲自操作还是让 Agent 操作，都映射到同一个 human key。项目页诚实写明 demo wallet 尚未完整 AgentBook 注册，因此保留签名校验并使用 deterministic fallback humanId。
【分析推断】这是 Principal-normalized Quota：配额应该绑定最终责任主体，而不是 API key、session 或 agent_id。

## 批判
"一个人一个身份"也会引入隐私、可恢复性和误封问题；Selfie/World ID 并不能证明"这个 Agent 当前具体动作获得了用户知情同意"。身份唯一性和动作授权必须分开。

## 迁移方向
Personal Agent 中把 quota / budget / 招聘投递次数 / 免费资源额度绑定 user principal，而不是绑定每个子 Agent。否则删掉 Agent3 再创建 Agent7 就能绕过限额。
