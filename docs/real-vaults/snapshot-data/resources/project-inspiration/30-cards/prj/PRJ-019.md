# DELPHAI

## 场景与痛点
团队做认证/交付计划时常问"5周内能不能让8人里5人通过考试？"普通 Copilot 容易给积极路线图，但不会真正计算成功概率，也不愿明确说计划不可行。

## 功能流程
输入团队/目标认证/人数/期限 → 多角色 Council 拉取学习要求和团队条件 → 确定性概率/容量计算 → Skeptic 检查数字和假设 → Guardrail 评估不可接受条件 → 多方辩论 → 输出 GO/NEGOTIATE/NO-GO。

## 技术栈（EXTRACTED）
11 Agent + 确定性引擎 + 真实 veto 权 + Foundry IQ + Azure AI Search/Learn MCP；公开 evaluation harness 和 proof transcripts；synthetic data。

## 三段可信度
- 【作者公开】核心原则"模型解释 reasoning，但不发明数字"；Skeptic/Guardrail 有真实 veto；evaluation harness 公开。
- 【分析推断】价值来自把"反对意见"从文本风格变成系统权限：Skeptic 不是说一句"有风险"，而是真能改变最终状态（veto_ids 影响 Conductor 决策）。
- 【未披露】11 Agent 是否必要未由消融证明；synthetic data 绕开了真实人力规划的数据噪声和组织政治。

## 代码锚点（commit 13286160b6）
- `src/agents/conductor.py` — ConductorAgent.reconcile（skeptic权重0.65+optimist0.35；决策GO/NEGOTIATE/NO-GO/REVISE；burnout_veto为真则强制REVISE）；negotiate（生成4反方案：延期+2周/加替补/替换最弱/辅导最弱+3周，按概率排序）
- `src/agents/skeptic.py` — SkepticAgent.challenge（per-candidate VETO：optimist≥50%且skeptic<25%直接veto；返回veto_ids）
- `src/agents/base.py` — BaseAgent/Turn 基类
- `src/agents/verifier.py` — VerifierAgent
- `foundry_agents.py` / `evals/run_evals.py` — evaluation harness
