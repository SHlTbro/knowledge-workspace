# EcoLafaek

## 场景与痛点
帝力每天产生大量垃圾，居民知道"哪里脏"，市政缺少统一实时可分析的空间数据；单纯做垃圾识别模型不能改变清运决策。

## 功能流程
居民 Flutter App 拍照+GPS → Nova-Pro 分类垃圾/严重度/环境影响 → 写入数据库+向量索引 → AgentCore Agent 自动链 SQL/Code Interpreter/Browser → 地图聚类与热点发现 → 公共 dashboard/管理侧安排治理。

## 技术栈（EXTRACTED）
Flutter + Nova-Pro + Titan Embed + TiDB(SQL+Vector) + Folium/Matplotlib + AWS AgentCore；浏览器与代码解释器工具链。

## 三段可信度
- 【主办方/作者公开】AWS 赢家公告称其把居民移动上报与 AgentCore 自主工具链结合；文档披露 Titan Embed、TiDB、Folium。
- 【分析推断】重点是"把低成本群众传感器变成决策层可用的空间事件流"，Agent 只负责把不同数据工具拼成行动信息。
- 【未披露】dashboard 实时数据规模有限；图像分类准确率、误报处理、政府实际采用、长期运维成本无独立数据；GPS/照片隐私与恶意上报未公开方案。
