# SEPARATION

## 场景与痛点
多 Agent 系统通常让各 Agent 各自推理、输出动作后再做 validator；但两个动作单独安全、组合执行会冲突（write skew），且最终执行后往往不可逆。

## 功能流程
两 Agent 同时形成对同一资源的不同指令 → airlock 拦住尚未提交的 tool call（半形成意图）→ 另一 Agent 异议介入 → 直接收窄参数(narrow)后继续原 turn（非 abort 整轮）。

## 技术栈（EXTRACTED）
TypeScript + Mozaik runtime；确定性 record/replay；600-run ablation；多角色共用同一模型（实验隔离的是架构变量而非模型差异）。

## 三段可信度
- 【作者公开】record/replay、600-run ablation、runtime bug 发现；多角色同模型。
- 【分析推断】适合代码/数据库/生产配置等高风险并发操作。
- 【未披露】真实企业流量、多模型供应商、复杂 invariant 长期误报数据。
