## 用户与痛点
一个 Personal Agent 如果同时持有邮件、日历、钱包、密码、财务记录和长期记忆，组合能力很强，但任何一个 prompt injection 都拥有巨大的 blast radius。反过来，如果每个 Agent 完全隔离，旅行 Agent 又无法向工作 Agent 问"下周三有没有空"。

## 功能流
服务为每个 MCP function 定义 declarative policy（origin=same-human / any-human / public，assurance=none / selfie / identity，executor=local / 0g，也可以 agentCallable=false）。调用者签名绑定 service domain、function、递归哈希后的参数、policy version、nonce、expiry 和 call id；服务端重新计算并验证，查询 World AgentKit 得到背后的匿名 humanId，再执行 per-function policy。高风险函数可以通过 MCP inputRequired 暂停本次调用，要求 World Selfie/Identity step-up，完成后自动恢复同一 invocation。函数只返回允许的答案或动作，私有数据库、银行余额、私钥和内部策略留在原服务里。

## 真正机制
【作者公开】项目直接把原则写成"share functions, not secrets"。例如 finance service 暴露 canCommit(amount,purpose)，而不是把完整交易历史给另一个 Agent；calendar 暴露 findCompatibleWindow()，而不是把所有事件导出去。
【源码级】hors-sdk 导出 createGate / definePolicy / defineConfig / hashArgs / hashBody；MCP adapter `hors(server)` 替换 registerTool 为 gated version，每个工具声明 `hors: "same-human"`；handler 收到 `ctx.hors: HorsContext` 而非 signature/wallet；调用者用 SIWE(EIP-4361) 签名绑定 endpoint+function+hashArgs+nonce+expiry；tools before hors() fail-closed with HORS_POLICY_ERROR。
【分析推断】这是 Function-level Zero Trust for Agents：授权单位从"整个 Agent/整个服务"缩小成"某个函数 + 某组参数 + 某个人类 origin + 某次 assurance"。

## 批判
humanId 证明"同一个真人"不等于证明这次意图获得了充分授权；函数粒度如果设计太粗，仍会泄露大量信息。跨供应商标准也需要解决 policy version、撤销、replay、设备被盗等现实问题。

## 迁移方向
把 local MCP/Personal Agent Tool Registry 改造成"函数级能力目录"：每个工具声明 principal_scope、arg_constraints、assurance、executor、side_effect_level。Researcher 可以调用 resume.get_skill_summary，却不能拿到整份私密简历；购物 Agent 能调用 budget.can_spend(299)，但不能读取银行卡信息。
