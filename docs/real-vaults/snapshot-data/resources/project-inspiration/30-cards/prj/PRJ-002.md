# Metamorph

## 场景与痛点
框架迁移牵涉路由/目录/依赖/API/配置；直接改真实仓库风险高、失败难恢复。

## 功能流程
输入代码库 + source→target（如 React→Next）→ Mapper 找文件、PackageManager 调依赖、多 Worker 并行改、Reviewer 检查（拒绝回 Worker，retry cap）、Coordinator 只观察 → Integration 在影子工作区真实安装/build → 用户主动 Apply 才进 Git 分支。

## 技术栈（EXTRACTED）
TypeScript monorepo（packages/@nikelyh）；Worker/Reviewer 并发限制；Coordinator 不用 LLM；Integration 加锁；Reporter 调用与安装/构建并行。

## 三段可信度
- 【作者公开】shadow copy、bounded retry、真实 build gate 等工程边界。
- 【分析推断】AI Coding 价值从生成速度转向变更可验证性与失败隔离。
- 【未披露】多框架/大型真实仓库迁移成功率、失败恢复成本 benchmark。

## 代码锚点（develop, 19123caa5a）
- `packages/@nikelyh/application/src/MigrationRunner.ts` — startMigration（cloneDirectory→持久化 plan→MIGRATION_STARTED）/ rollback（丢弃 shadow，原仓不触碰）
- `agents/IntegrationAgent.ts` — 影子工作区真实 build 作为 integration gate
- `agents/WorkerAgent.ts` / `ReviewerAgent.ts`（bounded retry）/ `CoordinatorAgent.ts`（非 LLM）
