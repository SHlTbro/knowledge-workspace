## 项目概述
ProjectPlanGuard 专门寻找"paper 上满足要求、现实中却难执行"的计划。企业项目计划可以满足模板、审批规则和资源填写要求，却仍可能在真实执行中失败：关键人同时被两个项目占用、依赖顺序不成立、工期没有缓冲。

## 功能流
输入 project plan → 抽取任务、人员、依赖、工期、规则 → 检查形式要求 → 进一步找 overload、时间冲突、依赖不可行和执行瓶颈 → 输出风险与修改建议 → PM 复核

## 真正机制
【主办方公开】ProjectPlanGuard 把数十分钟检查缩短到不足一分钟（团队报告数字）。
【分析推断】机制是 Compliance ≠ Feasibility：规则验证之后还必须做 execution simulation / constraint check。传统检查器常只验证"字段齐不齐"。

## 技术
公开材料没有披露模型、约束求解器、数据结构和 benchmark。无公开 GitHub。

## 批判
如果系统只是让 LLM 阅读计划后"觉得不现实"，它仍可能是包装。真正产品必须把资源、时间、依赖转换成可计算约束，并测误报/漏报。

## 迁移方向
给 AI Coding PRD 做 Feasibility Gate：先验证需求格式，再检查仓库是否有对应模块、测试入口、依赖、时间预算和权限。
