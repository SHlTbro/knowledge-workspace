## 项目概述
2036 Agentic Town 把 Agent 身份从一个 UUID 扩展为"谁在法律上能代表谁"。Agent 替人付款、签约、安排医疗时，必须回答：它现在是否仍被真实人/机构授权？这个 principal 是否死亡、失踪、失能、被监禁或未成年？

## 功能流
Agent → 解析 root → institution → principal → agent 的签名链 → 读取 principal 状态与 transaction category → 返回 Ed25519 签名的 proceed/refuse verdict → 业务 Agent 按 reason_code 行动并保存 cert_id

## 真正机制
【作者公开】项目把 Authentication、Authorization、Accounting 扩展到"人-Agent 社会"，医院、法院、警方、登记处等 institutional writer 更新 civil state；交易前的 Agent 只获得"允许/拒绝及后续动作"，不必得到敏感诊断。
【分析推断】真正可迁移的不是"AI 宪法"包装，而是 Principal-bound Dynamic Capability：权限不是 Agent 静态 scope，而是 agent binding × principal state × action category × time 的函数。

## 批判
Demo 中 institution keys 可自助申请，因为它是 synthetic sandbox；真实政府/企业部署必须绑定 PKI、强审计和权限发放。状态机设计也可能把复杂法律现实过度简化。

## 迁移方向
给 Personal Agent 做 principal-bound tool authority：同一个用户的 Researcher、Writer、Executor 不只各有 scope，还受"当前场景状态"约束，例如求职投递期允许创建草稿但禁止发送；支付场景超过金额即自动冻结执行权。
