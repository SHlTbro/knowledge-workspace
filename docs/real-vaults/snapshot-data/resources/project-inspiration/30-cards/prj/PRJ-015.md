# GibberLink

## 场景与痛点
两个语音 Agent 相互打电话时，传统链路仍是"LLM文本→TTS→声波→STT→文本"，为了机器之间交流却反复做人类语音编码，增加延迟和转换损失。

## 功能流程
两个 ElevenLabs Agent 先用英语交流 → 双方识别"对面也是 AI"并确认切换 → tool call 结束语音会话 → 用 ggwave 数据声协议继续同一 LLM thread。

## 技术栈（EXTRACTED）
ElevenLabs Agent + ggwave（WebAssembly 数据声编码）+ Web Audio API；gibbMode 工具需双方同时满足"识别为AI+对方确认"才进入。

## 三段可信度
- 【作者公开】两端都有 gibbMode 工具，必须同时识别+确认才切换；仓库提供 ggwave 编解码复现实验。
- 【分析推断】真正创意不是"机器人声音"，而是 capability negotiation + protocol switch：参与者能力变化时系统动态换协议，不把人类接口当永久底层。
- 【未披露】ggwave 不代表互联网 Agent 通信最佳协议；现实中直接数字链路通常更合理；安全/认证/可审计性未因压掉自然语言自动解决。
