## 用户与痛点
Agent-to-Agent marketplace 的经典问题是：一个 Agent 能发现另一个 Agent 并不等于它值得信任。链上 reputation 也可能被 self-review、集中账户互评和女巫网络刷高；而单纯做一次 RAGAS 质量分又忽略长期信誉。

## 功能流
查询 ERC-8004 Identity/Reputation/Validation 数据 → 计算 reputation pattern → 加入 RAGAS faithfulness / answer relevancy / context precision → 合成为 Trust Score → 检查是否达到用户阈值 → 达标才执行真实 HBAR 支付 → approve/block decision 都写入 Hedera Consensus Service。

## 真正机制
【作者公开】AgentRanker 不只算平均星级，还检测 concentrated/self-generated review；支付 gate 使用可配置 trust threshold。
【分析推断】核心是 Trust-before-Delegation：可靠性评估不是事后 dashboard，而是资源/权限/金钱委托之前的同步决策门。

## 批判
RAGAS 分数与真实业务可靠性之间仍有距离，且 reputation network 可以出现更复杂的协同刷分；一个"高 Trust Score"也不能推导出高风险动作可无人监管。需要把 capability、金额、失败成本等一起纳入授权。

## 迁移方向
给 Skill/MCP registry 增加"Observed Reliability"而不是只看 README：成功率、dangerous failure、版本新鲜度、最近一次验证、用户/Reviewer 信号。编排器只有在能力匹配且 reliability 达阈值时才自动调用，高风险工具即便分高也保留额外 gate。
