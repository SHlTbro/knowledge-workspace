## Agent Reliability Profile — 把"能力说明书"变成可被证伪的测试规范

**赛事/奖项：** C:\>DIR 2026 第 5 名；团队来自 MLCommons Financial Services WG。

**功能流：** 读取设计文档/配置导出/政策 → Profile Builder 生成 Level 1 Asserted Profile → 找出"设计意图"与"实际配置"不一致 → Profile Validator 把声明直接转成测试规范 → 主动尝试 falsify → 依据真实行为生成 Level 2 Validated Profile。

**真正机制：** 【作者公开】Profile Validator 的目的不是验证"看起来对"，而是主动尝试证伪；演示场景测试开放银行 Agent 是否严格遵守客户实际同意的数据共享范围。【分析推断】Asserted→Falsified→Validated 三阶段让"能力声明"成为可执行合约，而不是 README。传统 Agent card 是静态自述，这里把它变成测试入口。

**批判：** Profile 可靠性取决于证据覆盖度与测试生成质量。Level 2 不能证明所有未来输入安全，只能证明在指定测试范围内没有被成功证伪。

**迁移方向：** 给 MCP / Skill 建 Capability Profile：声明允许的文件根、可写动作、网络权限、不可逆行为；自动从 Profile 生成负向测试，故意要求越权写、路径穿越、未授权网络访问。
