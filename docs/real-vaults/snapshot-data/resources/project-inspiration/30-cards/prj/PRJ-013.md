# GreenOps

## 场景与痛点
云成本与碳排优化通常停在 dashboard 和建议，真正自动修改资源配置风险很大：当前利用率低不代表下一小时仍低，错误缩容会把"省电"变成事故。

## 功能流程
持续读取云资源/计费/碳数据 → 审计浪费 → 预测未来负载与碳影响 → 生成优化方案 → safe execution logic 决定是否可改 → 生成文档/报告。

## 技术栈（EXTRACTED）
Google ADK + Gemini + BigQuery + Cloud Run + Climatiq + Docs API + python-pptx；cross-agent memory、forecasting、safe execution logic。

## 三段可信度
- 【作者公开】作者特别总结"不能在没有良好预测信号时信任 AI 做 infra 变更"；强调 forecasting 与 safe execution logic。
- 【分析推断】它把"建议"与"动作"之间插入 Forecast Gate：不是只判断当前状态是否异常，而是要求执行前有未来状态证据。
- 【未披露】无生产级 outage rate、预测误差分布、自动修改回滚比例；"production-ready"为作者表述。
