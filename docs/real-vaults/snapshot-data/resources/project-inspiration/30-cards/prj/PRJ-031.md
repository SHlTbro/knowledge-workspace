## 项目概述
AgentPress 是一个 Agent 之间的信息市场：Agent 注册后获得 starter credits，提交 news signal；Herald 自动编辑器按确定性 8 因子评分，定时编译付费 edition；读者 Agent 支付 credits 后，80% 收入按编辑评分权重精确分给贡献者。

## 功能流
Agent 注册 → 提交 signal → deterministic rubric 即时评分与反馈 → Herald 定时汇编 → 读者付费读取 → ledger 精确分账 → leaderboard / status 反馈

## 真正机制
【作者公开】系统不是"LLM 当主编然后自己决定钱"，而是把可争议的内容判断压成透明 rubric，并把经济结算放到整数账本与 largest-remainder 分配里，保证收入守恒。
【分析推断】可迁移机制是"概率生成 + 确定性结算"：允许 Agent 在内容上模糊，但涉及积分、预算、贡献归属时必须进入可审计确定性层。

## 源码级真实符号（L2 commit 5f84853400）
- `scoreSignal(parsed.data, {recentHeadlines, pendingBeatCounts, agentSignalsIncluded})` — 确定性评分函数，返回 score + breakdown + feedback
- `ACCEPT_THRESHOLD`, `ACCEPT_REWARD` — 接受阈值与奖励常量（src/lib/constants）
- `creditAgent(agent.id, ACCEPT_REWARD, "reward", "Signal accepted by Herald")` — 积分记账
- `signalSchema` (Zod) — headline, body, sources[], tags[], beat
- 表 `signals`: status ∈ {accepted, rejected}, score, breakdown, feedback, editionId
- 表 `agents`: totalSignals, signalsAccepted, signalsIncluded
- 技术栈：Next.js 16, Drizzle ORM, Neon Postgres, Zod 4

## 批判
编辑评分虽然确定，但 rubric 本身仍可能偏置或被 gaming；没有长期验证这种经济激励是否真的提升信息质量。starter credits 属于封闭模拟经济，不等于真实支付合规。

## 迁移方向
给 AI Coding / 知识库多 Agent 做"证据贡献积分"：Agent 每提交一条可复验事实进入 ledger，只有后续被任务真实消费并验证后才获得积分。
