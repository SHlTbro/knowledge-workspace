## Space Lord — 高风险 Agent 的安全底座应该能做到"模型想写也写不了"

**赛事/奖项：** Hello Future Apex 2026 AI & Agents Track 1st，奖金 $18,500。

**功能流：** 本地 OpenClaw Agent 接收自然语言 → 通过 Hedera Agent Kit 查询钱包/交易所/投资组合 → 直接访问 SaucerSwap V2 contract → deterministic safety limits 在能力层约束可执行动作 → 主网读取与分析。

**真正机制：** 【主办方公开】deterministic safety limits 允许 Agent read but never write，并直接在 Hedera mainnet 工作。【分析推断】Capability Denial by Construction：安全不是每次让模型"判断自己该不该写"，而是从工具能力集合里根本不发写权限。Prompt guardrail 是软政策，capability surface 才是硬边界。

**批判：** 只读模式天然安全得多，也意味着项目尚未证明真正自主交易时的安全机制；"直接合约调用"减少中间层，也同时减少传统钱包 UI 的确认保护。

**迁移方向：** local MCP / Agent 工具拆为 read-only 与 mutation 两套 capability bundle。研究 Agent 永远加载只读 bundle；只有进入受控执行阶段才短时注入写工具。
