# Verdict

## 场景与痛点
B2B 支付前要核查公司制裁、欺诈历史和声誉；开放 Web 信息多但网页会变、可能有 prompt injection，普通研究 Agent 只会"搜完给总结"，不适合直接卡住真实付款。

## 功能流程
输入公司 → 先查 OFAC；命中则 deterministic hard BLOCK → 未命中才用 Bright Data MCP 搜索/抓取 → hostile-input sanitization → LLM 生成风险发现 → citation verifier 逐条确认来源 → 风险分数按透明基线+signed contributions → APPROVE/ESCALATE/BLOCK + PDF 审计报告。

## 技术栈（EXTRACTED）
Bright Data MCP + OFAC 确定性名单 + citation verifier + 透明风险评分；保留 counterparty 历史，复查突出"发生了什么变化"。

## 三段可信度
- 【作者公开】确定性 sanctions hard gate 先于开放 Web；网页当不可信输入做 sanitization；结论逐条反查证据；含 contradiction/adversarial check。
- 【分析推断】最值钱的是证据优先级：确定性法定名单 > 不可信开放 Web > LLM 解释层，而不是把所有来源扔进同一个 prompt。
- 【未披露】Apple/Wirecard/Bank Melli demo ≠ 真实金融 KYC benchmark；制裁误匹配、实体消歧、网页时效、法律责任更复杂；分数公式透明不代表公式正确。
