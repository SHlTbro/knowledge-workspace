# SprintForge

## 场景与痛点
Scrum Master 收到 Teams 转录 / planning notes 后，仍要手工抽 Epic/Story/Task/Owner/Blocker、查文档、建 Jira。

## 功能流程
读邮件及附件 → 提取工作项 → 识别 Azure/Microsoft 服务 → Docs MCP 找权威文档 → 补 acceptance criteria / 实现建议 → Jira MCP 建工单。

## 技术栈（EXTRACTED）
Microsoft Copilot Studio + MCP（Microsoft Learn Docs MCP + Jira MCP）；单会话 agent 组合提取/丰富/自动化；解决方案 managed.zip 低代码导入。

## 三段可信度
- 【作者公开】部分附件处理仍未完全实现。
- 【分析推断】价值在「非结构化 → 权威依据 → 结构化 action schema → 写入业务系统」链条。
- 【未披露】Jira 任务质量、人工修改比例、责任归属、长期维护成本。
- 注：readme 宣称约 70% 准备时间减少，属团队宣称、非独立验证。
