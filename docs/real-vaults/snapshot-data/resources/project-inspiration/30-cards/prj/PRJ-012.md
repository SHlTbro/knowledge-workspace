# Particle Physics Agent

## 场景与痛点
研究者/学生把自然语言粒子反应画成 TikZ-Feynman 图，需同时懂物理守恒、粒子数据和 LaTeX 语法；普通 LLM 容易画出"语法能编译但物理错误"的图。

## 功能流程
英/中文描述 → Planner 结构化反应 → KB Retriever 检索 150+ 示例 → Physics Validator 经 MCP 查 PDG/量子数 → Diagram Generator 生成 TikZ → TikZ Validator 本地编译 → 失败带 error report 重进 Generator "Correction Mode"，最多 3 次。

## 技术栈（EXTRACTED）
ADK 1.0 + Gemini 2.0 Flash/Pro；六个专职 Agent；ParticlePhysics MCP Server；顺序验证循环；报告可编译成功率 >95%（团队自报）。

## 三段可信度
- 【作者公开】ADK 六 Agent 架构、MCP 粒子数据工具、顺序验证优于并行、95%+ 可编译率。
- 【分析推断】最值得迁移的是"生成器与领域裁决器分离"：模型提候选，MCP 后确定性/权威系统有否决权；失败原因喂回生成器，不再问一个 LLM"你觉得对不对"。
- 【未披露】95%+ 是自报且 TikZ 语法成功 ≠ 物理正确；PDG 覆盖边界、高阶图、完整编译环境未独立验证。

## 代码锚点（commit 2158aa45a0）
- `feynmancraft_adk/agent.py` — root_agent（conditional correction loop，max 3 attempts；State Flow: plan→examples→physics_report→[tikz_code→validation_report] loop→final_response）
- `feynmancraft_adk/sub_agents/physics_validator_agent.py` — PhysicsValidatorAgent（output_key=physics_validation_report；工具 validate_quantum_numbers_mcp / validate_process_against_rules）
- `feynmancraft_adk/sub_agents/feedback_agent.py` — FeedbackAgent（output_key=final_response）
- `feynmancraft_adk/tools/physics/physics_tools.py` — parse_natural_language_physics（正则模式匹配，unphysical combination 时 can_generate_diagram=False）
- `feynmancraft_adk/integrations/mcp/mcp_client.py` — MCP 客户端封装
