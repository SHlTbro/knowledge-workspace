## 项目证据
- 赛事：ETHOnline 2026，Ledger "Extend to Ledger" 第二名。
- 项目页：https://ethglobal.com/showcase/preflight-mcp-1i1qm（源代码从 ETHGlobal 页面可访问）

## 用户与痛点
一个 Agent 可以读合约源码、名称和描述，然后判断"看起来没问题"并签名。但恶意资产/合约最容易伪装的恰恰是文本和 metadata。项目举的例子里，某代币声称拥有巨额流动性，链上却四年只有极少交易。

## 功能流
Agent 提议签名 → Preflight 不只读 contract text，而是拉真实历史行为与链上活动 → 在 install / read / trust / submit / allowed 五个边界检查风险 → 低风险可继续 → 高风险要求 Ledger 设备上的真人物理确认。

## 真正机制
【作者公开】项目主张"not what the contract says, but what it has done"，并用五个边界区分 Agent 进入真实签名的不同风险层。
【分析推断】这是 Behavior-over-Description：任何第三方 Tool / MCP / Skill 的说明都应该低于真实观测行为的证据权重。它和 Skeptic 一类理念相通，但落在高后果签名前的 runtime gate。

## 批判
历史"行为良好"的新合约仍可能未来作恶；行为信号也可能被刻意养号。安全决策需要把 code/static facts、history、counterparty、value-at-risk 和用户 policy 一起考虑。

## 迁移方向
给 MCP tool 做 runtime preflight：安装时审权限，读取时隔离不可信内容，执行前查过去 observed contract，提交前核对参数，高后果写操作还要检查 allowed scope。不要把所有安全逻辑塞在最后一个"Are you sure?"按钮里。
