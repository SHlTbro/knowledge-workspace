# SalesShortcut

## 场景与痛点
自由开发者/小团队靠销售伙伴手工冷启动获客：找潜客、研究公司、写提案、打电话、发跟进邮件全靠人串行，瓶颈在销售动作的吞吐而非创意。

## 功能流程
城市/行业输入 → Google Maps 找潜客 → 多研究 Agent 并行分析公司与竞争 → Proposal Agent 生成个性化方案 → Voice Agent 呼叫 → 邮件跟进与 Calendar 预约 → BigQuery 看板维护 funnel。

## 技术栈（EXTRACTED）
ADK + A2A + Vertex AI + Google Maps/Search/Gmail/Calendar/BigQuery/Pub/Sub + ElevenLabs；34 Agent、5 Cloud Run 微服务；fan-out/gather、review/critique、iterative refinement、HITL。

## 三段可信度
- 【作者公开】34 Agent、5 微服务、A2A 网络；作者称最难的是状态/一致性/并发/A2A 失败，不是写 prompt。
- 【分析推断】真正可复用的是"业务步骤拆窄职责 + 只在研究阶段 fan-out + 汇总前显式 critique + 外部动作保留监督"。34 只是规模，不是创新。
- 【未披露】无独立销售转化 benchmark；未证明 34 Agent 优于 5-8 Agent；冷呼叫合规/号码信誉/地区法规未公开。

## 代码锚点
无公开源码（no_public_source）。机制为作者公开架构描述 + 分析推断。
