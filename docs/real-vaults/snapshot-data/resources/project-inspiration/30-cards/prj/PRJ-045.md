## 项目证据
- 赛事：NanoClaw × Tavily Track 2026 第二名。
- 官方 winners：https://nanoclaw.dev/hackathon/
- 项目 PR：https://github.com/nanocoai/nanoclaw-templates/pull/47

## 用户与痛点
活动公司或小型机构做好 proposal 后，供应商价格可能在发送前变化。普通监控会发一句"价格发生变化"，然后人类自己重新翻文档、算 margin、找要修改的句子。Evidence Domino 试图把这段返工继续自动化。

## 功能流
approved source / supplier page → Tavily 定向检索 → 比较当前事实 → 若价格改变，重新计算 proposal margin → 定位受影响句子 → 生成带来源的 exact repair → owner 审批后再应用。Demo 中供应商价格从 40 美元涨到 55 美元后，系统会计算其对利润目标的实际影响。

## 真正机制
【作者公开】项目保留 raw evidence bytes、做 calculation、evidence retention、document repair 和 approval checks；作者报告 73 tests 通过，并强调 daily monitoring 默认 paused。
【分析推断】可抽象成 Evidence Change → Business Impact → Repair Candidate。传统 change detection 停在"发现变化"，这里多了一层"变化是否真的改变业务结论，以及需要修哪一个 derived artifact"。

## 批判
最大风险是传播链不完整。如果 proposal 某个数字通过复制粘贴出现在 Excel、邮件、PPT 等多个地方，只修正文档一处会制造新的不一致。所以生产版需要明确 dependency graph 和 source-of-truth。

## 迁移方向
当 PRD、契约或配置改变时，找出所有依赖旧 claim 的测试、文档、简历描述和 Agent Skill，生成 stale-candidate，不直接自动覆盖。
