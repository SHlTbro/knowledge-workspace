# Freight Room

## 场景与痛点
船舶延误会触发物流、财务、承运商、客户团队跨公司协调；传统流程靠不同邮箱和系统追人，demurrage/detention 成本在等待期间继续增长。

## 功能流程
Sentinel 监听 live AIS → 检测真实船只异常停泊 → 自动创建 Band response room → 运行时发现并招募当前事故真正需要的 Agent → 美国海关提单识别受影响进口商 → 物流 Agent 给恢复方案、Finance 按 Maersk tariff 算成本、Carrier 反驳条款 → 专职 Dissent Agent 攻击最佳方案 → quorum vote → 人类经理批准 → 生成审计 dossier。

## 技术栈（EXTRACTED）
7 Agent 横跨 LangGraph/PydanticAI/CrewAI；Band room @mention 协作；真实 AIS/海关/公开费率；runtime recruitment + institutionalized dissent。

## 三段可信度
- 【作者公开】7 Agent 多框架协作、真实公共数据、专职 Dissent Agent、quorum vote；importer 预到港匹配作者自标 inferred。
- 【分析推断】两个可迁移点：runtime recruitment（只在事故需要时招角色，不常驻全员烧 token）；institutionalized dissent（给反方明确任务和留痕，不期待普通 reviewer 自发挑错）。
- 【未披露】"所有数据真实公共"不等于生产链完整；跨公司权限、数据许可、真正执行恢复动作仍是大坑。
