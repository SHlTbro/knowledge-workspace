# Reversible Agent Actions

## 场景与痛点
Agent 做真实 tool call 后，常见"失败就 rollback"说法过度乐观：改文件能恢复、创建记录可能能删、发邮件只能补救、转账/外部通知甚至不可逆；把它们全叫 rollback 是在用一个词遮住五种责任。

## 功能流程
Agent 开始 transaction → 每次 tool call 记录 input/output/prior state → 动作分类 CLEAN/RESTORATIVE/TOMBSTONED/MITIGABLE/TERMINAL → 若后续失败，对可逆动作严格逆序补偿 → 不可逆动作生成明确 human intervention，不伪造"已撤销"。

## 技术栈（EXTRACTED）
MCP + action journal + 五级 reversibility taxonomy + rollback_transaction()；24 小时黑客松原型。

## 三段可信度
- 【作者公开】action journal、五级可逆性分类、rollback_transaction()；官方确认 ViyonTech 获企业 AI 赛道冠军。
- 【分析推断】真正可迁移的是 compensation semantics：Agent runtime 应像分布式事务一样，预先知道每种副作用的补偿合同。
- 【未披露】24 小时原型未证明跨 SaaS/API 补偿完备性；RESTORATIVE 依赖事前保存 prior state，外部系统并发修改可能让恢复覆盖别人新数据。
