## 用户与痛点
数据中心或远程机房里，工程师把 work order 发给现场技师，技师换线、换盘、贴标签后回传几张照片。真正麻烦的不是"识别照片里有什么"，而是确认照片是否能证明指定设备、端口、标签、替换件真的按工单完成，以及多轮回复中是否仍有证据缺口。

## 功能流
work order → 技师照片/后续照片 → 读取可见 identifier → 与工单要求逐项匹配 → 记录 matched / missing / conflicting evidence → 生成精确补拍/复核问题 → owner 最终在对话中确认并记录 review。

## 真正机制
【作者公开】模板保留原始 work-order 文件和 earlier reviews，会持续追踪缺失或冲突证据，而不是每张图独立做 caption；作者报告 38 项自动检查，覆盖缺失证据、冲突标签、replacement role、真实硬件照片和 follow-up image。
【分析推断】这可抽象为 Evidence Accumulation over Time：多模态 Agent 的目标不是"一次识图成功"，而是维护一份逐步补全的证据状态机。

## 批判
图像可见 ≠ 物理事实一定成立，照片可以过期、错位或刻意拍错对象；视觉模型也可能认错 serial/label。因此系统最重要的是"缺证据时继续保持 missing"，而不是强行完成工单。

## 迁移方向
对 AI Coding / FDE 验收也用同一思想：需求、截图、测试日志、接口响应、代码 diff 分别成为 evidence item，直到所有 contract 都有对应证据才完成；不要拿一张"页面看起来正常"的截图替代后端正确性。
