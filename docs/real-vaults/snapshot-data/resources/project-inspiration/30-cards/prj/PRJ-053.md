## 用户与痛点
自主 Agent 持有钱包或高权限凭据后，签名前常见做法是跑一层 policy / risk check。但很多风险判断依赖链上状态、代理合约版本、协议索引等动态数据。数据源虽然能返回结果，却可能落后真实世界几分钟甚至几小时。如果系统不把 freshness 当一等信息，"查到了"就很容易被误写成"安全"。

## 功能流
Agent 提交 unsigned transaction；presign 在 mainnet fork 上真实 simulate，读取 state diff 而不是只看 calldata，再跑 unlimited approval、proxy mutable logic、protocol invariant、unidentified counterparty 等规则。The Graph 层不只发现 subgraph，还实际发查询验证 conformance，并把 _meta block 与独立 chain head 比较，得到 lag。调用者给 freshness budget：同一个 Aave 调用，在 30 秒预算下可能是 low；在 1 秒预算下，如果数据跟不上则返回 unavailable。unavailable 是正式风险等级，不是异常兜底。中风险可升级 Ledger 物理批准，高风险甚至不送到设备。

## 真正机制
【作者公开】项目明确规定"No fresh indexed data, no green verdict"。而且 verdict 返回 deployment、lag seconds、simulated block age 等 provenance。
【分析推断】这叫 Freshness-bounded Evidence Gate：事实不只有 value，还必须有 age；当证据超过任务允许的 staleness，系统必须承认"我不知道"，不能把 data unavailable 静默降级成 no issue found。

## 批判
freshness 只能保证"数据够新"，不能保证数据源本身正确；模拟环境和真实执行之间还存在 race / MEV / state change。生产版应把 source integrity、simulation fidelity 和 freshness 分开。

## 迁移方向
RAG / Career Agent 的每个关键事实加 freshness_budget：招聘状态可能要求 24h 内，法规/价格可能要求 1h 内，静态技能文档可更久。超过 TTL 后不是继续引用旧缓存，而是输出 STALE_EVIDENCE / NEED_REFRESH。测试"旧事实误决策率"而不是只测检索命中率。
