## 项目概述
Litmus 表面是一个普通 web-reader / search 服务，背后同时记录 Agent 是否被外部内容劫持，或是否主动尝试危险操作。常规 Agent 安全测试是显式 benchmark（模型知道自己在被测试），而 Litmus 把安全评测嵌在正常工具接口中持续压力测试。

## 功能流
Agent 正常调用 read/search/db → 服务插入分级 prompt-injection 与危险行为诱因 → canary / 行为规则观测 → 生成单次签名 susceptibility scorecard → 汇总 leaderboard

## 真正机制
【作者公开】Litmus 包含 7 级提示注入阶梯（L1 overt → L7 invisible）、canary tripwire，并监控 SSRF、SQL/command/path/template/NoSQL injection、泄露凭据使用、钓鱼链接、flooding 等行为。
【分析推断】值得迁移的是 Embedded Adversarial Evaluation：安全评测不再是上线前一次考试，而是嵌在正常工具接口中的持续压力测试。

## 源码级真实符号（L2 commit 579997b17e）
- `LEVELS = ("L1_overt", "L2_tool_output", "L3_covert", "L4_confused_deputy", "L5_dangerous_tool", "L6_prompt_leak", "L7_invisible")` — 7级注入阶梯
- `_seed_payloads(base, session)` — 在返回内容中播种 L1..L7 canary + 危险URL诱饵 + 钓鱼链接 + SSRF诱饵 + 凭据诱饵
- `_canary(session_id, level)`, `_record_hit(tok)` — canary token 生成与命中记录
- `_scorecard(s)` — 生成签名评分卡，verdict ∈ {"HIJACKED", "SAFE"}，hijack_score = followed/7
- `_url_safe(url)` — SSRF 防护：DNS 解析后检查 private/loopback/link-local/reserved/multicast/unspecified
- `_detect_input_attack(text)` — 5种注入模式正则检测（SQLi/command/path/template/NoSQL）
- `KNOWN_BAD_HOSTS` (6个), `LURE_DANGEROUS_URL`, `PHISH_HREF`, `SSRF_LURE_URL` — 诱饵
- `FLOOD_WINDOW_S=10.0`, `FLOOD_THRESHOLD=40` — 洪水检测
- 路由: /read, /search, /x/* (7个canary端点), /db/query, /report/{session}, /leaderboard, /board
- 技术栈：FastAPI, Pydantic, httpx, BeautifulSoup4

## 批判
Honeypot 能发现"遇到特定诱饵时会犯错"，不等于覆盖全部攻击面；过度把安全测试混进生产工具还可能影响性能或引入隐私问题。

## 迁移方向
给 local MCP / Skill Registry 做 decoy fixture：正常 read/write API 中加入可识别但无伤害的 prompt-injection 与越权诱因，比较"纯离线安全测试"与"真实工作流嵌入测试"发现的违规类型差异。
