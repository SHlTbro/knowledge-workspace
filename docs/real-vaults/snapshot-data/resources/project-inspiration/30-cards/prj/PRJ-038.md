## 项目概述
Team a 帮助工程师选择最有效的故障诊断步骤，并进行安全测试以找出 root cause。故障现场最耗时间的是工程师面对几十个 dashboard 和日志，不知道下一步应该查什么。

## 功能流
【主办方公开】系统帮助工程师选择最有效的故障诊断步骤，并进行安全测试以找出 root cause。
【分析推断】最有价值的架构：观测现象 → 形成多个根因假设 → 按信息增益/风险排序 probe → 只执行安全探针 → 吸收结果 → 缩小根因集合。

## 真正机制
这是 Active Diagnosis，不是"RAG 查 runbook"。Agent 的下一步动作目标是最大化信息增益，而不是立即修系统。对 FDE 很重要：很多企业问题先缺"确定问题在哪"，并不缺一个能改配置的机器人。

## 技术与边界
ITIDA 官方没有公开模型、探针目录、数据集、执行权限、故障 benchmark 或代码仓库。只把"安全探针式根因诊断"视为主办方描述 + 分析推断。

## 批判
最大风险是所谓"安全测试"实际上仍具有副作用；如果探针权限过宽，诊断 Agent 自己就能制造事故。

## 迁移方向
做 SafeProbe MCP：只暴露 read-only metrics、log query、health check、dry-run、synthetic request。Agent 每轮只能选择一个 probe，并解释它区分哪些假设。
