# 伪需求 / 无真实痛点

## 典型表现
解决"技术上很酷"但没人真痛的问题；用户不会改变现有工作流，Demo 只有 happy path。

## 检测信号
找不到具体用户 / 具体场景；现有方式其实够用；用户不愿付费或切换；触发频率极低。

## 缓解 / 刹车
先写清"用户 + 场景 + 原方式痛点 + 触发频率"，让真实用户复述痛点；按问题频率 / 成本排序，而非技术炫度。

## 证据实例
[[PRJ-003]] [[PRJ-004]] 锚定真实业务流程而非凭空设想。
