# Career Agent 并行 fan-out + 单一投递 gate

## 用户场景
求职 Agent 替用户处理 JD 发现、公司研究、简历证据映射、面试准备；不能让一个 Agent 串行全做，也不能让投递动作无监督。

## 最小功能
- JD 发现、公司研究、简历证据映射、面试证据检查做并行 fan-out（4 专家）。
- 汇总器聚合后，最终投递动作走单一 gate（人批或确定性规则）。
- 复用 [[PTN-019]] 动态组队思想，Python/FastAPI 实现。

## 对照组
A：单 Agent 顺序处理同一批 JD；B：4 专家 + 汇总器（本实验）。

## 验收指标
同一 50 条 JD：总延迟、重复搜索量、错误匹配率、人工修改率；投递动作 0 例未经 gate 执行。

## 最大未知因素
4 专家的职责边界划分（重叠/遗漏）；fan-out 的 token 成本是否被延迟节省抵消。
