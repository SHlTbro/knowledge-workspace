## 实验目标
对项目做 Change Impact Map：代码 commit 后自动找到 README、PRD、架构图、简历项目描述中可能受影响的 claim，只生成 stale candidates，不直接改事实。

## 最小实现
1. 监听 git commit（或手动触发）
2. 代码 diff 分析：提取变更的函数/类/配置/API
3. 文档 claim 索引：对 README/PRD/架构图中的 claim 建立索引（claim 文本 + 关联的代码符号）
4. 影响映射：变更的代码符号 → 可能受影响的文档 claim
5. 输出：stale candidates 列表（claim 文本 + 关联代码变更 + 置信度）
6. 不自动修改文档，只提示

## 验收指标
真正漏改率（代码变更后文档确实需要改但未被检测到）、误报率（检测到但实际不需要改）、用户处理 stale candidates 的时间、文档与代码的一致性评分。

## 最大未知
文档 claim 与代码符号的关联准确率，以及架构图等非文本格式的 claim 提取难度。
