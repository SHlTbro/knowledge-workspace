## 用户场景
AI Coding 项目有 1,000+ 个函数，当前 coverage 只有 65%。工程师不可能一口气补齐。传统做法按 coverage 最差文件补测试，容易花大量时间测试没人调用的边缘代码，而真正关键的依赖链仍是空白。

## 最小功能
Python + FastAPI/CLI。
1. 用 ast/tree-sitter 生成函数与调用边。
2. 导入 coverage.py 的 missing lines。
3. 导入 git diff / recent change frequency。
4. 可选导入历史 failing tests / incident tags。
5. 为每个函数计算：Risk = UncoveredSeverity × DependencyReach × ChangeRecency × FailureHistory
6. LLM 只负责阅读 top-N 函数和 caller context，生成"为什么先测它"和测试候选，不允许修改 risk 基础分。
7. 自动在 shadow workspace 生成测试后运行 pytest，只有真实 failure-catching / passing evidence 才计入收益。

## 复用什么
- BlindSpot 的 Structural Test Debt 机制（PTN-058）
- AST 静态扫描 + call graph + coverage.py 集成
- LLM 只读 read-only tool，不执行被扫描代码

## 新做什么
- 四因子风险公式（UncoveredSeverity × DependencyReach × ChangeRecency × FailureHistory）
- git diff / recent change frequency 集成
- 历史 failing tests / incident tags 集成
- shadow workspace 自动生成测试 + pytest 验证

## 对照
A. 传统 coverage 最低优先。
B. 只按 caller count 优先。
C. Impact-Weighted 风险优先。

## 验收指标
- 固定 20 个新增测试预算下的 seeded defect 捕获率
- 高传播半径缺陷召回率
- 新增测试平均执行时间
- false-priority rate
- LLM 建议被真实测试执行接受的比例
- 每捕获一个真实缺陷的 token / wall-clock 成本

## 最大未知
静态调用图质量。如果 Python 动态 dispatch、framework magic、reflection 很多，call graph 会错。第一版应把 runtime trace 作为可选增强，而不是假装 AST 能看穿宇宙。
