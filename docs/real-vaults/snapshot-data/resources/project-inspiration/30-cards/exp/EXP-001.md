# FastAPI 并发写操作的意图气闸

## 用户场景
FastAPI 后端多个 Agent / 请求并发修改同一资源（订单、配置、库存），单独合法但组合冲突（write skew），事后 DB 报错时副作用已发生。

## 最小功能
- 复用：意图注册 + 联合冲突判定 + narrow 收窄的思想（不照搬 Mozaik/TS）。
- 新做：在 FastAPI 维护 IntentRegistry（资源→待提交意图）；写操作先注册、不执行；对同一资源并发意图跑确定性冲突函数（基于业务 invariant，如余额不得为负）；冲突时返回"收窄后的安全参数"而非 409 整单拒绝。

## 对照组
A) 直接写 + DB 约束事后报错；B) 加本气闸。

## 验收指标
write-skew 用例 100% 被拦截或收窄；正常并发误拦率 < 5%；p99 额外延迟设上限并实测。

## 最大未知因素
业务 invariant 能否形式化、误报率高低。
