## 用户场景
Personal Agent / Career Agent / AI Coding Agent 已经能调用多个 MCP，但"工具返回成功"不代表数据适合当前决策。招聘岗位缓存是 3 天前的；GitHub/代码索引比 working tree 落后 2 个 commit；价格/API 状态来自 6 小时前。Agent 仍然可能拿这些 stale facts 做不可逆写操作。

## 最小功能
Python + FastAPI 做薄层 Evidence Gate，不改 MCP Server 本身。每次工具返回值额外封装 source_id / observed_at / source_version / content_hash / freshness_budget / evidence_class / claim_scope。Action Planner 在任何有副作用的工具调用前列出依赖的 evidence_id。Gate 只做确定性判断：age <= freshness_budget、source_version matches、required evidence class present、no dependency marked stale。不满足时只允许 REFRESH / STEP_UP / UNAVAILABLE。

## 复用什么
- presign 的 Freshness-bounded Evidence Gate 机制（PTN-061）
- "No fresh indexed data, no green verdict" 原则
- unavailable 作为正式风险等级而非异常兜底

## 新做什么
- MCP 返回值封装 schema（7 个字段）
- Action Planner evidence 依赖列表
- 确定性 Gate 逻辑（4 条规则）
- 三种结果：REFRESH / STEP_UP / UNAVAILABLE
- freshness_budget 由 domain policy / tool contract 给默认值，LLM 最多提出收紧建议不能自己放宽

## 三组对照
A. 当前常见做法：工具返回什么就直接用，缓存 TTL 统一固定。
B. 按工具类型固定 TTL（招聘 24h、代码索引 10min）。
C. Freshness-Aware：每个 claim/action 自己声明 freshness_budget，并要求版本/hash 对齐。

## 测试集
100 个 synthetic cases：25 个数据仍正确但变旧；25 个 stale 后已发生实质变化；20 个 source 暂时不可达；15 个 source version 与决策引用 version 不一致；15 个多来源冲突。动作分成 read-only、reversible write、irreversible/high-impact 三档。

## 验收指标
stale-evidence dangerous action rate、unnecessary refresh rate、false block rate、refresh 后结论改变率、high-impact action 在证据不足时的 fail-closed rate、额外 wall-clock/token/API cost、每次决策能否追溯到 exact source version。硬门：高后果动作使用 stale/unknown evidence 的次数 = 0；source unavailable 不能自动降级成 no-risk。

## 最大未知
freshness_budget 本身不是客观真理。股票价格可能要求秒级，招聘 JD 可能一天，代码契约可能必须与 commit 完全一致。第一版不要让 LLM 自由发明 TTL。
