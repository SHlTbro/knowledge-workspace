## 实验目标
不要把所有安全逻辑塞在最后一个"Are you sure?"按钮里。在 install/read/trust/submit/allowed 五个边界分层检查。

## 复用什么
- Preflight MCP 的 Behavior-over-Description 机制（PTN-057）
- 五边界检查（install/read/trust/submit/allowed）
- "not what the contract says, but what it has done"

## 新做什么
- 为 MCP tool 定义五边界 preflight 检查点
- install：审权限范围；read：隔离不可信内容（防间接提示注入）；执行前：查过去 observed behavior；提交前：核对参数；高后果写操作：检查 allowed scope
- 真实观测行为 > 自我声明描述

## 如何验证
对比：A. 传统"最后一个确认按钮"；B. 五边界 runtime preflight。指标：dangerous action 拦截率、误报率、用户操作流畅度、安全事件率。最大未知：observed behavior 数据的积累需要时间。
