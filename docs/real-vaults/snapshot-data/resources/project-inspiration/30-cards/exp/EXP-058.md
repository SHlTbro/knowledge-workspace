## 实验目标
Personal Agent 监听任务不要只设 cron。保存 blocker predicate + benchmark，只有 capability test 从 FAIL→PASS 才唤醒。

## 复用什么
- Votive 的 Capability-triggered Retry 机制（PTN-062）
- capability sweep + pass/fail matrix + 可验证 attestation

## 新做什么
- blocker predicate schema（任务描述、阻塞条件、capability test 定义）
- capability test runner（每次模型/工具更新后运行）
- FAIL→PASS 唤醒逻辑（不是时间到了，而是阻塞条件变化）
- 资源隔离 cell（资金/计算/API key 相互隔离）

## 如何验证
对照：A. 固定日重试；B. Capability-triggered。指标：无效调用数、首次可执行发现延迟、误唤醒率、资源消耗。测试场景："等某模型能可靠处理 300 页合同""等某招聘站支持稳定自动投递"。
