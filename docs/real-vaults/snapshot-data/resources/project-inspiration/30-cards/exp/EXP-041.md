## 实验目标
面向企业故障的主动诊断 Agent：不把所有日志塞给 LLM，而是让 Agent 主动选择安全探针，按信息增益缩小根因集合。

## 用户场景
企业线上系统出现"响应变慢 / 部分请求失败 / 某 Agent 工具超时"。现有做法要么工程师手工翻十几个 dashboard，要么把所有日志一股脑塞给 LLM。

## 最小功能（48h）
1. incident 输入：症状、时间窗、服务名
2. hypothesis registry：Agent 生成 3-5 个互斥根因假设
3. safe probe catalog：Prometheus/metrics query、日志过滤、health/readiness、dependency status、synthetic GET、config read、dry-run
4. 每轮 Agent 只能选一个 probe，声明：区分哪些假设、预期结果 A/B 如何更新置信度、是否有副作用
5. side-effect ≠ NONE 的 probe 一律拒绝自动执行
6. evidence ledger：结果进入 ledger，直到根因置信度达标或升级人类
7. 输出：root_cause_candidate + evidence trail + untested alternatives

## 合理对照
- A：传统"所有日志一次性给 LLM"
- B：固定 runbook 顺序
- C：SafeProbe 按信息增益动态选择只读 probe

## 验收指标
准备 30 个可重复故障 fixture（DB connection pool exhausted、Redis timeout、DNS failure、downstream 429、bad config、stale deployment、memory pressure、queue backlog 等）。测：
- Top-1 root cause accuracy
- 定位所需 probe 数
- token / 时间成本
- 危险动作次数（目标 0）
- 证据可复核率
- 当 ground truth 不在假设集时的正确 abstain 率

## 最大未知
最大难点不是模型推理，而是 probe catalog 是否足够好。如果所有 probe 都提供低信息量结果，聪明 Agent 也只能聪明地浪费时间。这个实验真正要验证的是"让 Agent 主动选择安全实验"是否比"被动摄入更多日志"更有效。
