# 旗舰：Agent Decision Airlock（决策气闸）

## 用户场景
事件触发（webhook / 邮件）的 FastAPI 自主 Agent 处理"会产生写操作"的任务（自动处理工单 / 配置变更）。要求：动作在意图层过闸、概率/确定/人工分流、高后果动作必须人批。

## 最小功能
- 事件入口（FastAPI webhook）接收任务。
- 意图层：待执行写操作先进入 airlock 注册表，不直接执行。
- 三边界路由器：确定性校验（纯函数：格式 / 规则 / 计算）→ LLM 处理模糊判断 → 命中高后果规则进入"待签字"。
- 气闸：对并发 / 冲突意图做确定性冲突检测，冲突给出收窄建议。
- 人批接口：待签字动作确认后才执行；全程留痕（SQLite）。
- 复用 [[PTN-001]] / [[PTN-003]] / [[PTN-005]] 思想，全部 Python/FastAPI 新实现，不抄 TS。

## 对照组
无气闸、全 LLM 直接执行的同一 Agent。

## 验收指标
1) 注入的冲突 / 越权写操作 100% 在意图层拦截（不触达执行）；
2) 高后果动作 0 例未经人批执行；
3) 确定性路由子系统单测 100% 通过；
4) 正常任务误拦率 < 10%；
5) 每个决策可回放、可追溯到规则 / 事件。

## 最大未知因素
高后果规则与冲突 invariant 的形式化完备性（漏一条即是洞）；48h 内只做窄域、不追求通用。
