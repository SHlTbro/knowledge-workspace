# 问题
起号期内容随机探索、期与期之间无关联，观众没有"追更"理由，算法也难给连续推荐。purpose.md 把"栏目化机制"列为重点对标维度（Bob"挑战用AI做100件事"、IT咖啡馆"GitHub一周热点"、飞天闪客【闪客】前缀）。S-005 提供了第一份可直接拆解的抖音编号系列样本。

# 各方解法对比（单来源分点，全部出自 S-005）
1. **双编号体系**：抖音标题挂总期数"｜第116期｜"，口播开场自报"挑战用AI做100件事 第98期"[00:00:00]——栏目名自带终点目标（100 件事 = 有终点的内容赛程），编号是观众可感知的追更进度条。EXTRACTED。
2. **固定开场公式**：期数自报（1 秒）→ 本期清单预告（"本期视频我给大家准备了18个工作流，设计、图像、音频三个领域"[00:00:02]-[00:00:05]）→ 价值承诺 → 固定老话脚本（"还是那句老话"[00:00:19] 引出低配兜底/云部署）。每期同构，制作可模板化。EXTRACTED。
3. **固定收尾公式**：资料库回扣 + "点赞、收藏" + 签名句"我是Bob同学，咱们下期再见"[00:11:27]-[00:11:37]。"下期再见"把单视频结束变成连续剧悬念。EXTRACTED。
4. **重复式老话的一稿两用**："还是那句老话"对老观众是熟悉感/身份认同，对新观众随后补全必要信息（低配怎么办）——重复不冗余。EXTRACTED + INFERRED（"一稿两用"为机制归纳）。

## trade-off
- 编号系列降低每期选题与脚本成本、积累追更粘性；代价是格式绑死（固定段落挤占单期创新空间）、栏目名带终点（"100件事"临近完结需提前设计续栏目接棒）。INFERRED（依据：结构推断，端外涨粉数据未验证）。
- 双编号并行（总期数 vs 挑战编号）两边吃辨识度，但未做解释时新观众会困惑"到底第几期"。INFERRED（本例口播与标题编号差 18 期，无任何说明）。

# 推荐用法
- 抖音起步期先定三件套：**栏目名（带目标感/前缀）+ 期数编号 + 固定开场 3 秒自报**；清单型内容套"N 个工具 + 域分块"模板。
- 编号放标题与封面（本例标题挂"第116期"），口播自报控制在 1 秒内，不占前 3 秒生死线。
- 收尾固定句式至少含：资源/下期预告钩 + 签名句；老话脚本选一条每期必复用的高频痛点（如低配适配）。

# 反面教训
- 双编号不解释=新观众认知摩擦；单栏目内编号与平台总期数二选一对起步期更干净（INFERRED）。
- 编号系列 ≠ 简单加数字：本例的系列感来自"固定开场公式 + 固定收尾公式 + 重复老话"三件套齐备，只挂数字不固定脚本没有追更效果（INFERRED，依据 S-005 结构对照）。
- 不适用于强时效蹭热点内容（编号承诺的是系列一致性，热点单发更灵活）。
